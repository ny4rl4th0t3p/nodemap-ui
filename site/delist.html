Request delisting

Operators of a self-advertised public RPC node can have its individual record removed from this map. The node keeps counting in the anonymous aggregates; only the endpoint row disappears. This hides the node from this map, not from anyone running their own crawler.

Removal requires proof of control of the node's node_key: the P2P identity key, not the consensus key. It cannot sign blocks. Producing the proof reads the key; nothing restarts, nothing is written, nothing is gossiped, and nothing from this project runs on your node.

Procedure

  1. Sign, with the node's node_key, the exact text 
    delist <node_id> from nodemap <YYYY-MM>
    where <node_id> is your node id in lower-case hex and <YYYY-MM> the current UTC month. The signature is a plain ed25519 signature over those bytes: no hashing, no framing. Package it as 
    {"node_id":"<hex>","pubkey":"<base64 of the 32-byte public key>","signature":"<base64 of the 64-byte signature>"}
  2. Encrypt that object to this instance's key, delist.asc. The public key alone identifies your node, so the proof must never travel in the clear: 
    gpg --import delist.asc
gpg --encrypt --armor --recipient <the key's id> proof.json
  3. Open a new discussion in the delist category, titled exactly delist, and paste the armored text, the block from -----BEGIN PGP MESSAGE----- to -----END PGP MESSAGE-----, into the body. Pasting is the point: an attached file is not read. A code fence around it is fine. A workflow picks it up within minutes, posts one reply, and deletes the thread.

What happens then

The reply is the same whether the proof verified or not. A valid proof shows as your endpoint disappearing after the next run, and in nothing else. The proof is valid for the month it names and the month after. The list the crawler reads holds only a salted hash of your node id; the salt is never published, and nothing in this repository identifies a delisted node.

The discussion names the account that opened it for as long as it exists. If you need to be unlinkable even from the maintainer, use a throwaway account; the proof verifies on its own, so a relay through someone else works too.
